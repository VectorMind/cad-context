# Project working state, publication and recovery

Status: user-approved storage and project-navigation direction, 2026-11-08.

A project has a portable ID, durable model source outside disposable cache, and an independently configured publication location. All generated working geometry is confined to <workspace-cache>/projects/<id>/cad/<generator>/; tests, proofs, regenerated baselines and review output also stay in cache. Source is trusted local Python and versionable specifications, exact parameters/curves, reference assets, toolchain locks and continuation records. Git operations remain maintainer-owned. No irreplaceable information may exist only in cache.

The catalog binds local source and shared publication locations separately. Bindings are machine-local/environment-owned. Published metadata and files must be readable without executing or even possessing local source, and after deleting cache. A source snapshot with complete per-file and archive SHA256 checksums is explicitly published under reference/source.zip/source.json, excluding generated 3D exports, cache, Git internals and bytecode. Restore validates the archive before writing and refuses any existing destination, traversal, symlink or duplicate member. Keep useful original references/native authoring sources and historical generator code; do not preserve intermediate generated model archives. Equivalent geometry regeneration is required, not byte identity.

project rebuild fully verifies individual 3MF print packages and 2D exports, measures native viewing geometry against references, and runs confined project-specific reproduction/proof scripts. Lightweight viewing GLBs need not satisfy print topology; they are never print releases. Logs, measurements and output hash ledger remain local. Publication refuses stale source, unverified builds and changed verified output bytes. project publish atomically replaces web/latest with only declared GLBs and actively displayed reference views; it also snapshots continuation source. It never creates a print release. Viewer regeneration never writes Drive or replaces published models.

Print packaging is an explicit project release <id> YYYY-MM-DD[-label] action. Only declared individual-piece generic 3MFs and a release manifest are copied. No current directory, automatic dates, implicit switching or overwriting existing dated packages. project freeze checks every package checksum and marks the release frozen. Subsequent changes require an explicitly named new release. Printer/slicer settings and physically tested fit remain distinct from geometry/appearance acceptance.

Navigation: /projects lists catalog projects; /projects/<id> displays published GLBs, source recovery links and dated release downloads. /projects/<id>/workbench is the selected project's local mutable review surface. /viewer/<generator> is a local generation tool. Legacy /project redirects to /projects. All file routes are allowlisted and realpath-confined; no arbitrary source-directory exposure.

Release freshness must never be inferred from a filename revision, folder date, mesh validity or a successful integrity checksum. New release manifests record the source identity and per-file generator mapping. Project view compares each release's source identity with the published viewer snapshot and exposes same-source, different-source, legacy-untracked or no-published-source. The UI explicitly warns about legacy/untracked and different-source downloads. Matching provenance establishes source alignment only, not appearance approval or physical fit. Historical releases remain historical until a user-authorized dated release is exported from the declared current print generators. A review must check every mapped model, approval status, cached export ledger and viewer hashes; checksums alone cannot prove that the chosen model is current.

Publication staging cleanup is confined to the expected parent and must handle Windows/Drive read-only files and directories. Permission-error retries may clear write protection only inside that staging tree; never broaden cleanup to an arbitrary or redirected path.

For the animal project, r014 comparison geometry and historical bear/elephant shapes are reconstructed from preserved curves/settings into cache, rather than read from Drive archives. A fresh-cache rebuild and source-archive restore test are required before cleanup. Preserve existing delivered legacy print packages under their original release date. No new print freeze is implied by storage migration.

Verified export checkpoints support --reuse-exports for proof-only fixes; changed generator/input identity or artifact bytes refuse reuse. Shared source snapshot updates compare the last observed source revision and refuse to overwrite another machine silently. Snapshotting excludes credentials, environments and generated exports; explicitly imported inputs/references may retain essential source geometry. Original Fusion-specific comparison bevels need not reproduce exactly: durable cubics regenerate source-outline baselines, while current models retain independent full measurements and print proofs.
